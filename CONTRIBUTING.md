# Contributing to Awesome Busabase

Thank you for helping improve this collection.

## Inclusion Criteria

A project should:

- Integrate directly with Busabase or materially help developers build on Busabase.
- Have a public repository or documentation page that explains what it does.
- Be usable, maintained, and relevant to the section where it is listed.
- Add distinct value instead of duplicating an existing entry.

Commercial and closed-source tools are acceptable when they provide a meaningful Busabase integration and link to substantial public documentation.

## Submission Format

1. Add the entry to both `README.md` and `README.zh-CN.md`.
2. Place it in the most specific existing section and keep entries alphabetized by display name.
3. Use this format: `[Project](https://example.com) - A concise description that starts with a capital letter and ends with a period.`
4. Link to the canonical project page. Do not use URL shorteners, referral parameters, or tracking links.
5. Add a new section only when at least two projects belong in it.

Descriptions should state what the project does and why it is useful. Avoid marketing claims such as "best," "leading," or "revolutionary."

## Pull Requests

- Submit one project or one tightly related group of projects per pull request.
- Explain how each project integrates with Busabase.
- Confirm that all links work and that both language indexes contain equivalent entries.
- Check spelling and grammar before submitting.
